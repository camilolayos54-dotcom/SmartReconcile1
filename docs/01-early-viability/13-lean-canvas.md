## 1. Business Model Overview (Lean Canvas Table)

| Canvas Section | Content & Details |
|---|---|
| **1. Problem** | • High manual reconciliation overhead (15–40 hours/week per finance team).<br>• Delayed monthly book closing (5–10 business days).<br>• Direct financial leakage from uncaptured bank fee discrepancies (0.2%–0.5% GMV). |
| **2. Solution** | • Java 21 high-throughput deterministic engine for sub-millisecond 99%+ exact matching.<br>• Python Agentic AI for parsing unstructured PDFs and resolving discrepancies in <30 seconds.<br>• React + Tailwind CSS dashboard for interactive audit approval. |
| **3. Unique Value Proposition** | The only hybrid reconciliation platform combining high-speed Java deterministic matching with explainable Python Agentic AI root-cause analysis and SOC-2 auditability. |
| **4. Unfair Advantage** | Dual-core Java/Python architecture with strict mathematical guardrails preventing LLM hallucination in production accounting ledgers. |
| **5. Customer Segments** | • Neobanks & Fintech Platforms.<br>• Payment Service Providers (PSPs).<br>• High-volume E-commerce Merchants handling >50k transactions/month. |
| **6. Key Metrics** | • Deterministic Matching Accuracy (>99.9%).<br>• Monthly Book Close Compression (>80% reduction in close days).<br>• Discrepancy Resolution Time (<30 seconds per incident). |
| **7. Channels** | • Direct B2B Outbound Sales to CFOs and VP of FinOps.<br>• Partnerships with Payment Gateways & Acquiring Banks.<br>• Accounting Firm Referrals & System Integrators. |
| **8. Cost Structure** | • Cloud Infrastructure & Database Hosting (AWS / GCP).<br>• LLM API Token & Inference Consumption Costs.<br>• Core Engineering & Customer Success Operations. |
